## Meta technology used

ProtocolSmith uses Muse Spark 1.3 through Meta Model API.

Muse Spark:

- Infers compatibility changes from paired API evidence
- Produces typed structured compatibility plans
- Compiles findings into a constrained adapter specification
- Designs a discriminating active experiment
- Assesses the evidence returned by that experiment

Model output is treated as untrusted until deterministic validation succeeds.

## Demo scope

The demo highlights only functionality created during the hackathon:

1. The unchanged legacy client succeeds against API v1.
2. The same client fails directly against API v2.
3. ProtocolSmith discovers the incompatibilities.
4. Muse designs an evidence-gathering experiment.
5. ProtocolSmith compiles and executes a constrained bridge.
6. The unchanged client succeeds through that bridge.
7. Deterministic checks produce a verification receipt.

## Known limitations

ProtocolSmith is a focused hackathon prototype, not a production-ready arbitrary API proxy.

Current limitations include:

- One controlled application domain
- One known endpoint family
- A deliberately small transformation allowlist
- Explicitly disclosed lossy date reconstruction
- No arbitrary production credentials
- Remote targets blocked unless explicitly enabled
- Additional redaction and isolation required for production data

These limitations will be stated clearly in the demonstration and submission.
